# AI-Agent_for_EduPlatform
Системный анализ и проектирование AI-агента для образовательной платформы

## 1. Бизнес-контекст

По наблюдениям образовательной платформы EduPlatform многие обучающие использует внешние AI-инструменты для решения тестовых заданий вместо самостоятельного изучения учебных материалов и выполнения заданий. Это снижает количество вовлеченных в учебный процесс обучающихся и не позволяет оценить уровень освоения материала. Тогда было решено внедрить ai-агента в платформу, чтобы обучающие научились использовать ai-агента не для решения задании, а для помощи в изучении учебных материалов и прохождении тестов.

На данный момент есть **проблемы**:

- обучающиеся не прорешивают сами задания тестов, а скидывают их сразу в нейросеть;
- обучающиеся не изучают учебные материалы;

Внедрение AI-агента должно **помочь ученикам самим изучать материалы и проходить курсы**.

### Цели проекта и метрики:

| Цель | Метрика (KPI) | Базовое значение | Целевое значение |
|------|---------------|------------------|------------------|
| Увеличить количество обучающихся, которые будут изучать учебные материалы| Доля обучающихся, изучивших учебный материал | 40% | 65% |
| Увеличить количество обучающихся, которые будут самостоятельно прорешивать тестовые задания | Доля заданий, выполненных самостоятельно | 40% | 65% |
| Не допустить снижения успешности прохождения курсов | Процент успеха | 94 % | 94% |

**Важно**: AI-агент не должен предоставлять готовое решение тестового задания, если запрос пользователя направлен на получение ответа вместо самостоятельного решения. Агент должен предоставлять ответ на вопрос, давать пошаговые подсказки и рекомендации.


### Границы системы (Scope)

**In scope**
- ответы на вопросы по материалам курса
- поиск информации в учебных материалах через RAG
- объяснение сложных тем
- предоставление подсказок к заданиям
- анализ ошибок обучающегося
- получение прогресса студента из LMS
- персональные рекомендации по обучению

**Out of scope**
- предоставление готового ответа на тестовое задание
- создание и редактирование курсов
- выставление итоговых оценок
- изменение результатов тестирования
- управление аккаунтами пользователей
- хранение учебных материалов как первоисточника

## 2. Требования

### Функциональные требования

- В системе должна быть возможность отправлять текстовые запросы AI-агенту
- Система должна уметь определять обучающегося, его прогресс и курс, который он проходит
- Система должна использовать только материалы курсов, на которые записан обучающийся
- При формировании ответа система должна использовать найденный учебный контекст
- При отсутствии учебных материалов по вопросу система должна сообщить об отсутствии достаточной информации и не формировать ответ на основании непроверенных данных
- При запросе на предоставление готового ответа на тестовое задание система должна отказать и предложить альтернативную помощь: подсказку или объяснение
- При анализе неправильного ответа обучающегося система должна объяснить допущенную ошибку и предоставить подсказку для самостоятельного исправления без предоставления правильного ответа.

### Нефункциональные требования

- Система не должна предоставлять обучающемуся данные других пользователей
- При поиске информации система должна учитывать права доступа пользователя
- Система должна сохранять информацию о запросах пользователя и результаты их обработки
- 95% запросов должны обрабатываться не более 5 секунд
- AI-агент должен быть доступен не менее 99.5% времени в месяц

## 3. Use case

Основной успешный сценарий:

1. Обучающийся отправляет текстовый запрос AI-агенту.
2. Система отпределяет обучающегося, его прогресс и контекст текущего курса.
3. Система проверяет доступ обучающегося к курсам.
4. AI-агент передает запрос в сервис поиска учебных материалов.
5. Сервис возвращает нужные фрагменты материала.
6. AI-агент передаёт вопрос и найденные материалы языковой модели.
7. Система формирует ответ и рекомендации, если они нужны.
8. Обучающийся получает ответ.

Альтернативные сценарии:

Сценарий 1: Материалы не найдены.

Система сообщает обучающемуся и преподавателю курса, что материалы не найдены. 

Сценарий 2: Нет доступа к курсу.

Система сообщает обучающемуся, что у него нет доступа к материалам курса, и подсказывает, что ему нужно сделать для получения доступа.

Сценарий 3: LLM или RAG недоступны.

Система сообщает о временной невозможности обработать запрос и предлагает повторить запрос позже.

Сценарий 4: Обучающийся просит готовый ответ.

Система сообщает пользователю, что она не может предоставлять готовый ответ на задание и предлагает подсказку или объяснение.

## 4. Стейкхолдеры

**1. Обучающийся**

Роль: Основной пользователь платформы

Интересы:

- Получать понятные объснения тем и ответы на вопросы
- Разбираться в собственных ошибках
- Получать персонализированные подсказки с учётом своего уровня знаний
- Не тратить много времени на поиск нужной информации

**2. Преподаватели**

Роль: Эксперт предметной области и участник учебного процесса

Интересы:

- Повысить самостоятельность обучающихся
- Помогать обучающимся лучше усваивать материал
- Сохранять качество и академическую добросовестность обучения
- Сократить количество однотипных вопросов преподавателю

**3. Заказчик**

Роль: Владелец платформы

Интересы:

- Не допустить снижения успешности прохождения курсов
- Привлечь новых обучающихся
- Повысить конкурентоспособность платформы за счёт внедрения AI
- Снизить отток обучающихся с платформы

**4. Системный аналитик**

Роль: Выявляет и формализует требования стейкхолдеров, определяет взаимодействие компонентов системы и согласует техническое решение с бизнес-целями

Интересы:

- Составить требования, которые совпадают с ожиданиями заказчика и стейкхолдеров
- Составить требования, которые реализуемы командой разработки
- Обеспечить однозначность и непротиворечивость требований
- Подготовить модели данных и сценарии взаимодействия
- Определить границы системы

**5. Команда разработки**

Роль: Исполнитель

Интересы:

- Реализовать продукт, который будет совпадать с ожиданиями заказчиков и стейкхолдеров
- Реализовать продукт с приемлемой производительностью, стоимостью и сложностью сопровождения
